# Vibe Coding 规范

> 分两层：**AI 协作规范**（我该怎么干活）和**项目开发规范**（代码该怎么写）。
> 全局红线见 `$DSH_HOME/AGENTS.md`；本文只写本项目增量，冲突时以全局红线为准。

---

## 一、AI 协作规范

### 1. 每轮开工协议

1. 先读 `AGENTS.md`，再读 `TODO.md` 的状态快照
2. 涉及检索 / 接口 / 表结构时，补读 `architecture.md` 与 `PRD.md` 对应章节
3. 确认本次工作属于哪个里程碑；完成后必须更新 `TODO.md`

### 2. 计划与确认门槛

以下情况**先给 3 行计划**（改哪些文件 / 怎么验证 / 什么风险），等确认再动手：

- 新增或改动 ≥3 个文件
- 任何删除、批量改写、数据库 schema 变更
- 改鉴权、租户隔离、检索主链路
- 引入新依赖、改部署方式

单文件、无删除的小修可以直接做，但要在收尾说明里交代。

### 3. 一次只做一件事

- 不夹带重构；顺手发现的问题写进 `TODO.md` 的「待办 / 待决」，不在本轮改
- 不擅自升级依赖大版本
- 一个提交只包含一件事

### 4. “验证”的定义

说“验证通过”之前，必须满足至少一条：

- 跑过命令并看到预期输出（贴关键行）
- 接口 / 浏览器实测走通主流程
- 相关测试全绿

**禁止**：没跑就说验证过；用“应该”“大概”“理论上”包装结论；编造输出。

### 5. 收尾格式

固定四段：

1. **结论**：做了什么
2. **依据**：命令、输出、截图、提交 hash
3. **风险与遗留**：明确列出没做的、可能坏的
4. **下一步**：可选项，不替用户做决定

### 6. 提交纪律

- **默认不 commit**；用户明确说“提交 / commit”，或本轮计划里包含提交并已确认，才执行
- message 用英文，动词开头：`feat:` / `fix:` / `refactor:` / `docs:` / `chore:`
- 不 amend 已推送的提交，不改写历史，不擅自切分支

### 7. 状态同步

- 里程碑完成：更新 `TODO.md` 状态快照
- 新增接口：`architecture.md` 补一行
- 新增环境变量：`.env.example` + `development.md` 同步
- 改命令 / 目录：`AGENTS.md` 与 `development.md` 一起改

### 8. 不确定时

- 给 2 个方案 + 推荐，让用户选，不自己挑一个往下做
- 缺信息：说清要读哪个文件、需要用户提供什么，不脑补
- 做不到：直接说，并给替代路径

## 二、项目开发规范

### 1. 分层

| 层 | 职责 | 禁止 |
|---|---|---|
| `src/api_server.py` | HTTP 参数、鉴权、错误码、SSE 组装 | 写业务逻辑、直接写 SQL |
| `src/services/` | 业务与持久化（auth、kb_store、admin、storage） | 处理 HTTP 细节 |
| `src/rag/` | 入库、切分、检索、缓存 | 感知 HTTP / 前端 |
| `web/src/` | UI 与交互 | 绕过 `api.ts` 直接 fetch |

### 2. 身份与租户（不可协商）

- 所有用户接口用 `Authorization: Bearer <token>`
- `tenant_id`、`user_id` **一律从 token 推导**，忽略客户端传的 `X-Tenant`
- 会话、消息、反馈、文档操作都必须带 `user_id` / `tenant_id`
- 管理接口统一 `Depends(require_admin)`；越权返回 403 或 404，不泄露资源是否存在

### 3. 数据库

- 迁移只允许 `CREATE TABLE IF NOT EXISTS` 和 `ALTER TABLE ADD COLUMN`
- 不删列、不改类型；新列必须有默认值
- 一次业务写多张表，放在同一个 `get_conn()` 上下文里
- 时间统一存 UTC（`datetime('now')`），只在展示层转本地

### 4. API 约定

- 路径：用户侧 `/kb/*`，管理侧 `/admin/*`，认证 `/auth/*`
- 错误码：400 参数、401 未登录、403 无权限、404 不存在、429 限流、500 服务端
- SSE 事件顺序固定：`meta → citations → token* → done`；异常发 `error` 后关闭
- 长任务：立即返回 `task_id`，状态查 `/admin/tasks/{id}`，不让请求阻塞等 embedding

### 5. 前端

- 请求集中在 `web/src/api.ts`，组件不直接 `fetch`
- token 存 `localStorage`；任何 401 统一清 token 回登录页
- 管理入口仅 `role=admin` 可见，但**前端隐藏不等于权限**，后端必须再校验
- 改完 `npm run build`；本仓库提交 `web/dist`，本地部署直接挂载

### 6. 知识库写入

- 上传 / URL 导入必须异步：任务表 + 轮询 + 审计
- 文件名清洗，限制后缀与大小（当前：md/txt/pdf/docx，≤20MB）
- 软删除保留 30 天；超期彻底删除必须写 `purge_doc` 审计
- 入库后 `bump_kb_version`，查询缓存自动失效

### 7. 日志与密钥

- 日志走 `log_event` / `logger`，不用 `print`（临时调试除外）
- 密码只存 scrypt 哈希；日志、审计、提交信息里不出现明文
- `.env` 不进 git；新增变量同步 `.env.example`

### 8. 测试矩阵

| 改动 | 必跑 |
|---|---|
| 检索 / 切分 / 提示词 | 50 条评测，四个指标不低于上次 |
| 表结构 / 账号 / 会话 | `pytest tests -q` |
| 前端 | 登录 → 提问 → 引用 → 反馈 → 管理页 |
| 上传 / 导入 | 上传 → 任务 done → 可检索 → 删除 → 恢复 |

测试保功能，评测保效果，两件事都要做。

### 9. 文档同步

- `PRD.md` 是需求唯一真源；架构变化同步 `architecture.md`
- `TODO.md` 记录状态快照与待决问题，不靠聊天记忆
- 新命令写进 `development.md`，不要只留在对话里
