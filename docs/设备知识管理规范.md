# 设备知识管理规范

版本：v1.0
适用：制造业设备与工艺知识库（demo / 后续租户）
维护：管理员

---

## 1. 目的与范围

本规范规定设备文档从**收集、入库、检索、引用到下线**的全过程要求，保证：

1. 回答有据可查，检索不到时明确拒答；
2. 文档来源合法、版本可追溯；
3. 删除可恢复，操作有审计；
4. 不同租户、不同用户的数据互不可见。

适用于所有进入知识库的文件与网页，不适用于聊天记录、临时笔记。

---

## 2. 术语

| 术语 | 定义 |
|---|---|
| 租户 | 一套独立语料与 collection 的使用方，如 demo |
| 文档 | 一个入库单元（一个 md/pdf/docx/txt 文件，或一个网页） |
| 块（chunk） | 文档切分后的检索单元，带 source_path 与 chunk_index |
| 软删除 | 移出检索但保留文件与元数据，30 天内可恢复 |
| 彻底删除 | 删除文件、向量与元数据，不可恢复 |
| 审计 | 记录谁在何时对哪个对象做了什么 |
| badcase | 用户点踩或人工标记的错误回答 |

---

## 3. 角色与职责

| 角色 | 权限 | 职责 |
|---|---|---|
| 管理员 | 文档增删改查、审计、用量、账号创建 | 维护语料质量、处理 badcase、执行备份 |
| 普通用户 | 问答、本人会话、反馈 | 提问、点踩、指出引用错误 |
| 系统 | 异步入库、30 天清理、缓存失效 | 保证状态一致、写审计 |

**管理员可见范围**：管理员可查看本租户全部会话与反馈（客服与质量分析需要）；普通用户只能看自己的会话。该范围写入产品说明，变更需评估隐私影响。

---

## 4. 文档分类与元数据

每篇文档至少记录以下字段（`corpus.csv` 或管理页）：

| 字段 | 必填 | 说明 |
|---|---|---|
| title | 是 | 文档标题 |
| model_no | 是 | 适用型号，如 X1 / P1 / A1 mini |
| doc_type | 是 | 故障码 / 维护 / 操作 / 参数 / 概念 |
| version | 是 | 文档版本，如 v1.0 |
| effective | 是 | 是否生效（1/0） |
| source_url | 是 | 公开来源地址 |
| license | 是 | 许可，如“可转载·禁止商用” |
| pages | 否 | 页数或块数 |
| notes | 否 | 备注 |

约定：

- 型号无法确定时，`model_no` 填 `通用`，不得猜测。
- 同一文档存在多版本时，只让最新生效版本进入检索，旧版本保留记录、标 `effective=0`。
- 来源不明或许可不明的文档，**禁止入库**。

---

## 5. 命名与目录

```text
data/tenants/{tenant_id}/
  fault_codes/     故障码文档
  manuals/         手册与操作指南
  uploads/         管理页上传与 URL 导入
```

文件命名：

```text
{型号}_{类型}_{版本}_{主题}.md
例：X1_fault_code_v1.0_HMS-0300-0100-0001-0003_热床过温.md
```

- 只用中文、英文、数字、下划线、连字符；
- 不含空格、括号、日期区间；
- 上传文件由系统加 8 位随机前缀，避免重名；
- 禁止 `..`、绝对路径、盘符。

---

## 6. 来源与版权

1. 只允许**公开**设备文档：厂商 Wiki、公开手册、公开故障码说明。
2. 每篇必须在 `corpus.csv` 记录 `source_url` 与 `license`。
3. 禁止公司内部资料、客户数据、付费文档、未授权转载内容。
4. 网页导入需遵守目标站点条款；抓取频率保持克制。
5. 引用展示时保留来源路径，便于追溯。

---

## 7. 入库流程

### 7.1 文件上传

1. 管理员在管理页选择文件（md / txt / pdf / docx，≤20MB）；
2. 系统校验后缀与大小，写入 `uploads/`；
3. 创建入库任务，状态 `pending → processing`；
4. 解析 → 清洗 → 切分 → embedding → 写入 Chroma 与 BM25；
5. 成功后写 `kb_files` 记录并 bump 版本；失败写错误原因。

### 7.2 URL 导入

1. 管理员填写公开网页地址；
2. 系统调用 Node + Edge 渲染，转 Markdown；
3. 落盘后走同一入库流程；
4. 需登录或反爬的页面，先导出 Markdown 再上传。

### 7.3 入库检查单

- [ ] 后缀与大小合规
- [ ] 正文非空（PDF 扫描件需 OCR，当前不支持）
- [ ] 编码为 UTF-8
- [ ] 去重：content hash 已存在则跳过
- [ ] 切分后每块 ≥ 200 字符（不足会合并）
- [ ] 来源与许可已记录
- [ ] 任务状态为 done，且能检索到

---

## 8. 切分与检索约定

| 项 | 约定 |
|---|---|
| 切分 | Markdown 标题优先，再递归切分；chunk 500，overlap 50 |
| 合并 | 小于 200 字符的块与相邻块合并 |
| 清洗 | 去 YAML front-matter、`> 来源：`、媒体资源章节 |
| 召回 | 向量 20 + BM25 20，RRF 融合，取 top 8 |
| 精确码 | 命中 `\d{4}-\d{4}-\d{4}-\d{4}` 时按原文包含预置 |
| 拒答 | 证据不足时只回答「不知道」，禁止编造 |
| 引用 | 每条回答附来源文件与片段，最多 5 条 |

---

## 9. 版本与生效

1. 文档更新时保留旧版本文件，`effective` 置 0；
2. 新版本入库后重新切分与 embedding；
3. 检索默认只返回生效版本；
4. 版本变更需在审计中记录（当前通过重新入库的 upload 记录体现）；
5. 不允许直接覆盖旧文件内容而不留记录。

---

## 10. 删除与恢复

| 操作 | 行为 | 可恢复 |
|---|---|---|
| 软删除 | 移出向量与 BM25，保留原文件与 `kb_files` | 30 天内可恢复 |
| 恢复 | 重新入库该文件，块数恢复 | — |
| 彻底删除 | 超过 30 天自动执行：删文件、删元数据、写 `purge_doc` 审计 | 否 |

规则：

- 删除前必须确认影响（该文档被哪些回答引用）；
- 恢复按钮同时出现在文档列表与审计页；
- 彻底删除不可逆，审计保留操作记录；
- 批量删除需管理员二次确认。

---

## 11. 权限与审计

1. 所有管理操作需要管理员角色，普通用户访问返回 403；
2. 审计字段：时间、操作人、动作、对象、说明；
3. 动作类型：`upload_doc`、`import_url`、`delete_doc`、`restore_doc`、`purge_doc`；
4. 审计日志只追加，不修改、不删除；
5. 会话与反馈按用户隔离，管理员查看全租户会话属授权行为。

---

## 12. 反馈与 badcase 闭环

1. 每条回答可点赞/点踩，点踩需选择原因；
2. 反馈进入 badcase 池，按租户隔离；
3. 管理员每周处理一次：
   - 答非所问 → 检查切分与检索；
   - 引用不对 → 检查文档质量与元数据；
   - 信息过期 → 更新文档版本；
4. 处理后记录结论，必要时加入评测集；
5. badcase 不直接删除，保留追溯。

---

## 13. 备份与恢复

| 项 | 约定 |
|---|---|
| 工具 | `python scripts/backup.py` |
| 内容 | `storage/app.db` + `data/tenants` + `corpus.csv` |
| 向量 | 可选 `--with-vectors`；不备份也可从语料重建 |
| 频率 | 每次批量入库前、每周一次 |
| 保留 | 默认最近 7 份，可调 `--keep` |
| 恢复 | 停服 → 覆盖 `storage/app.db` 与 `data/tenants` → 重启 → 校验文档数 |

注意：运行中备份 SQLite 使用在线备份 API；向量库建议停机或低峰备份。

---

## 14. 评测与回归

1. 评测集：`eval/eval_set_v2.csv`，当前 100 条（单文档 40 / 概念 11 / 跨文档 10 / 多跳 6 / 库外 33）；
2. 指标：DocHit@5、可答拒答数、库外拒答率、延迟；
3. 触发条件：改切分、检索、提示词、模型后必须重跑；
4. 通过标准：四个指标不低于上次；
5. 结果写入 `eval/results.csv`，并更新 `docs/基线评测报告.md`；
6. 评测集与语料同源，结论只用于回归，不外推为线上效果。

## 15. 附录

### 15.1 文档登记模板

```csv
file,title,model_no,doc_type,version,effective,source_url,license,pages,notes
X1_fault_code_v1.0_HMS-0300-0100-0001-0003_热床过温.md,X1 热床过温, X1,故障码,v1.0,1,https://...,可转载·禁止商用,2,
```

### 15.2 审计动作对照

| action | 含义 |
|---|---|
| upload_doc | 上传并入库 |
| import_url | 网页导入并入库 |
| delete_doc | 软删除 |
| restore_doc | 恢复软删除 |
| purge_doc | 超 30 天彻底删除 |

### 15.3 禁止事项

- 禁止把公司内部资料、客户数据、付费文档放入 `data/`；
- 禁止手工修改向量库文件；
- 禁止绕过管理页直接改 `kb_files` 状态；
- 禁止在日志、审计、提交信息中写入密码或 token；
- 禁止删除审计记录。
